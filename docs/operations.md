# 日常使用与运维

## 启动与在线

1. 打开 DeepSeek 工作台，进入 SurfCore 概览。
2. 检查 QQ 桥接与机器人账号在线状态。SnowLuma 应登录雨酱使用的机器人账号。
3. 在 **SurfCore → B站 → B站账号** 查看「回复与 @ 监听」。显示「收件箱可读」表示最近一轮成功。
4. 语音后台按需拉起。遇到语音问题时优先检查当前任务与后台状态，保留现有工作台会话。

这是本机部署。需要持续在线时，电脑和工作台须保持运行，网络、账号和桥接服务也须可用。关机和系统睡眠会中断本机服务。

## QQ 与 B 站

- **QQ 接错账号**。先检查 SnowLuma 的在线进程和机器人身份。SurfCore 会校验机器人账号，再放行收发。若两个账号的 OneBot 适配器同时争用相同端口，先停用重复适配器或分配独立端口。
- **B 站能登录却没回 @**。先看「回复与 @ 监听」，再检查这条 @ 是否出现在雨酱的收件箱。当前部署每三分钟轮询一次，唤醒后还需要模型处理和平台回执。确认送达以原评论楼层为准。
- **B 站显示监听错误**。按页面提示区分登录失效、网络故障、平台限制和会话唤醒失败。收件箱失败会保留上次处理位置，下轮再试。
- **主人正在忙**。减少主动提醒，在已有对话中按情景决定是否用语音或图片。

## 模型、媒体与费用

- **DeepSeek**用于日常聊天。**阿里云百炼**用于辅助，短聊与字幕整理已有验收。百炼通用工具调用、学生券实际抵扣须分别核对。
- **Seedream**用于图片生成。QQ 生成后发送使用已有媒体工作流。遇到限额或生成失败先看服务与媒体回执，避免重复生成。
- **快速语音与 IndexTTS2**适合不同的语音场景。两套模型按需交接，空闲退出以释放内存，减少争用显存。低资源时优先等待释放或改用文字。
- **搜索**已有搜索链路及 ModSearch 接入记录。改动搜索提供方时按独立验证结果切换。
- **费用提醒**按每天 5 元的用户偏好设计，定位是提醒。火山方舟和百炼的实际计费以各自账单为准，券抵扣以账单字段为准。

## 备份和恢复

改动前保存对应配置或源码的副本，记录改动文件与适用版本。按模块回退，再重开对应服务。验收时分开记录本机状态、平台读取、模型处理和最终送达。凭据只在本地输入和保管，日常文档只记录配置位置的类型及需要检查的状态。
